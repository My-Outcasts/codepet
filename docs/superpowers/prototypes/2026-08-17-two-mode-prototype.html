Seven things worth trying

  • Run the beacon task. “Write your positioning one-pager” → Marketing’s specialist takes it, works in four honest steps, and hands you a draft. Read it opens the real document; approving is what files it in Library and closes the task.
  • Then press “Something else” and walk through “Talk to 5 potential users” — a task byte cannot do for you, so it prepares it and records what you learned into your decisions instead.
  • Refuse the room. Ask a decision-shaped question, then press Just answer me. The expensive path should never be the one that happens by default.
  • Set the tier to “Ask me” in Developer, then run a task. Every step stops for a tap — the friction the third tier exists to remove.
  • Set it to “Let it run” and run the same task. It commits without showing you the diff, which is exactly the rail this design amends on purpose.
  • Ask it to merge to main, or to deploy, or to delete something. No tier permits it, so all three refuse.
  • Click Roadmap, then Start on the Engineering task. You land in Developer with the instruction carried over — the handoff, without a modal.

The mode-specific group at the top changes; the five company surfaces never move, because a roadmap task and the code that satisfies it belong one click apart. Beside the conversation sits an inspector that holds one tab per output — a draft, a diff, a preview.

Rule 1Chat is the only place work happens The five surfaces feed context slices and expose verbs; pages browse and manage state. A Start on Roadmap dispatches into whichever mode owns that verb.
Rule 2The mode gates the backend, never the sentence Ask reaches the nine cloud departments. Developer reaches code — Local on your own CLI at 0 credits, Cloud on the deployed Managed Agent. Where a run executes is the session’s business.
Rule 3One lifecycle, one card grammar proposed → running → result → review → committed, and only committed writes to context. Same exec log, same Stop, same hues on both sides.
Rule 4Tabs are for outputs, not for runs Parallel work is N cards in one conversation. Comparing results is N tabs in the inspector. Neither competes with RECENT/SESSIONS for the identity of the work.

Ask

Where Plan went

.plan was never “write me a plan” — it was the money gate. ChatMode.convenesRoom is true only for Plan because a convened decision measures ~$0.20 against ~$0.005 for an ordinary turn, so a casual Ask could cost forty times what it looked like. Deleting the pill deletes that brake, so the brake moved rather than vanished: the companion offers a room, priced in credits, and your tap is the permission. The + menu carries a manual door for when you already know.

Dollars stay internal — pricing is locked to credits with chat at ~0.25 so it feels unlimited, and a USD figure would publish our cost of goods. The ~10 credits on the card is derived (0.25 × the measured ~40×), not decided; the pricing spec owns the real number.

Gold · you owe a decision
A draft awaiting approval, or a room’s recommendation. The only hue that means the product is waiting on you.
Violet · the companion suggests
A proposal you can decline — including the convene offer, with its price on the button.
Blue · you are being asked
A question only the founder can answer, and the capture box that records the answer into decisions.
Teal · capability
One tap, not a judgement. Turning a tool on, which later work cites as a receipt.
Green · committed
Work that reached your branch or your Library. The only state that has written anything.
Muted · a receipt
“Noted.” It should recede, never compete.

First run

Don’t teach the UI. Hand them a first win.

A founder signing in for the first time does not need a tour of tabs and tiers — they need to watch their company do one real thing. Onboarding has already taken the brief and scaffolded a roadmap, so the first screen can be specific instead of welcoming. Play the first hour starts here, and the open with the first task already run switch compares the two openings without leaving the story.

 Task waitingFirst task already ran
What they seebyte, and one named task from their own briefa finished draft, with the inspector already open
Spent on arrivalnothing3 credits of the trial, before they asked
First impression“it understood my brief”“it already did the work”
Riskthey still have to press somethingspending someone’s money unasked, and being wrong in public
01The hero is never empty The roadmap exists before they arrive, so the beacon names a real task. Run it, not Get started.
02The first run is the tutorial Trial-funded, log shown in full, and it involves a department handoff — so within a minute they have met a second character and learned they have a company.
03The inspector opens itself, once The first draft arrives as a tab without being asked. The panel is taught by use, not by an arrow pointing at it.
04One sentence per first occurrence The first gold card, the first room offer, the first commit each get a single line — then never again. No modal tour: guidance is in-context, which is already the rule.
05Developer stays dormant No repo, no empty session — one honest offer to link a folder or connect a repo. Same pattern as the dormant departments in the stage-aware scaffold.
06Empty states carry the instruction “Your conversations appear here.” “Approved work lands here.” The absence explains itself instead of looking broken.

Decided: pets are the voice

Five voices, eight departments — and one gap

A department is a function; the pet is who speaks for it. So the cast appears on the first screen, the specialist signs the work it writes, and the room is cast rather than labelled — crash makes Engineering’s objection, not a nameplate. This is DepartmentCompanions.map as it already exists on the kept branch, which means it is not a clean 1:1, and the honest version of that is worth keeping on screen.

What this decision costs

Three pets doing two jobs is defensible — nova covering Marketing and Sales reads as one person wearing two hats, which is exactly what happens in a small company. But Product has no voice at all, and null is sitting unused. The cheap fix is casting null → Product and drawing it; the alternative is admitting Product is not a department in this product. Either way it is now a launch-blocking art task rather than a nice-to-have.

Two things deliberately not done

No companion picker. That step was dropped on 14 Aug as “a question with no consequence” — byte is simply the host, and the specialists introduce themselves by arriving. No modal tour. A tour teaches the chrome; the first run should teach the loop — run, review, approve, filed.

When it goes wrong

A demo where everything succeeds hides the design

Codepet’s pitch is that it never pretends. That claim is only testable on the unhappy paths, so they are part of the design rather than error handling bolted on later. Jump to the When it goes wrong chapter above to watch all five, or read the rule they share: say what happened, say what you did not do, and charge nothing for a failure.

The ruleA failure is never billed Assertions check the ledger, not just the message: out of credits, an outage and a red suite all leave spent unchanged.
The patternEvery refusal offers the other backend Two backends is not just a cost choice — it is the redundancy that keeps half the product alive when the other half cannot run.
The upgradeA rejection is information “Wrong approach / too big / not now” writes to decisions via the same remember verb the interviews use. Most tools discard this.
The endingMerged by you The PR is the last thing Codepet does. Use case 4’s success signal is the founder merging it — so the story now plays that beat and files the receipt.

Running more than one thing

Text deliverables are independent. Code is not.

That single fact decides the concurrency model, and it lands differently on each side. Three departments drafting three documents touch nothing shared; two code runs in one folder fight over a working tree — the collision this repo already solves with worktrees.

AskParallel is native N runs are N cards in one transcript, department attribution telling them apart. Comparing their results is what the inspector’s tabs are for.
DeveloperOne active run per session A session owns a branch. Concurrency means more sessions — Local needs a worktree-or-queue rule, Cloud parallelises naturally in its own sandbox.
CostA cap, and a live total Three simultaneous dept runs is 3× spend with no extra thought required. Cap concurrent runs (3), and show committed credits while they run.
WasteWarn on a dependency The roadmap has dependsOn. Launching “write the pricing page” while “decide pricing” is still running should say so — proposed, not yet decided.

Still yours to decide

Overview. The living progress dashboard, the centre-framed company map, the project briefing and the first-run spotlight all ship on main, and this shape has no slot for them. Either Overview retires and the Ask hero plus the Do this next beacon carry “where am I,” or the Codepet wordmark clicks through to it as the one page above the five. Recommendation: the wordmark — it costs one route and zero sidebar space, and retiring it deletes shipped work to solve a problem we have not measured.
