Two controls instead of four.

The composer's control row had three department chips, a ••• overflow, and a fourth chip that only appeared when you picked from that overflow — so the row had no fixed shape and eight departments had three separate doors. This collapses it to one button, and turns ＋ into a real capability door.

01The control row

Switch between what ships today and what's proposed. The proposed row is one control narrower and — the part that matters — always the same width.

Why one button
The chip row changed shape depending on what was selected
deptChips renders the first 3 of the roster (2 in the 380pt dock). A department armed from the overflow menu was invisible, so it got promoted to its own extra chip — a patch that exists only because a menu selection had nowhere to show. The row was 3 chips, or 4, and you couldn't learn its shape. An armed button is visible, so the patch stops being needed.
Why the menu is cast-signed
The row reads in the same order the answer is signed
crash · Engineering, pet first — because the reply arrives as Nova · Marketing. Three pets cover six departments, and the repeat is shown rather than hidden: one person wearing two hats is what happens in a small company. Every row's pet comes from DepartmentCompanions.specialistId, the same function the send calls, so the menu can never promise a pet the reply then doesn't sign.
Why "Anyone" is a row
The off state finally has a name
Deselecting today means clicking an armed chip a second time. Letting byte route it is a real choice, so it's a row you can pick, with a checkmark saying it's what you have.

02What the ＋ is for

It held three prompt starters that are already cards on the empty hero, plus the room, plus the department leftovers. Its own code comment defends it as "a quick-actions menu (NOT a file picker — the app has no attachments)" — an accurate description of a control with no idea what it's for. It now answers one question: what does this turn get to see, and how hard should it work?

The finding
Codepet already had 5 of Claude's 8 rows and 5 of ChatGPT's 9
They weren't missing — they were parked in the Environment page, two navigations from the only place you'd want them. That's what this redesign is actually for. The one genuine absence was the file row, which both competitors put first.
Why every row has a second line
You had to ask what "Convene the room · ~10 credits" meant
The answer had been sitting in RoomOffer.detail() the whole time — "4 departments argue this question and hand you a recommendation" — reachable only by hovering, which nobody does before spending 10 credits. ChatGPT captions every row; Claude captions none. ChatGPT is right, and that question is the evidence.
Why attaching is cheap now
The chat runs on Sonnet 5, not the Haiku I assumed
CHAT_MODEL = "claude-sonnet-5" — the first Sonnet in the high-resolution vision tier. 2576px on the long edge, 600-page PDFs, and no beta header. A screenshot gets a real read, not a downgraded one. Images are downscaled to that tier client-side before encoding, which is where the cost is decided — so tuning it never needs a deploy.

03What this doesn't show

Worth saying out loud before the team reacts to it.

Honest gaps in this prototype

  • The pets are CSS, not the real sprites. The app draws char-crash and friends as pixel art. Whether macOS renders a pixel-art sprite inside a native menu row is genuinely unknown and only settles on screen — the documented fallback is a text-only crash · Engineering, still cast-signed.
  • These are HTML menus, not NSMenu. Two-line rows and the exact metrics are what macOS decides. Treat the layout as intent, not a screenshot.
  • Nothing here is wired. The spec and a 12-task plan are written and committed; no Swift or TypeScript has been implemented yet. The freeze slips for the attachment work — that was a deliberate call with the cost stated.
  • The real risk isn't visual. ClaudeMessage.content is a string, and buildMessages merges same-role turns by concatenating them. Widen it for attachments without fixing that line and you get "[object Object]" in the prompt — no error, no crash. That's the one thing most likely to ship broken, and it's invisible in any mockup.
